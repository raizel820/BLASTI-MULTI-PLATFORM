# BLASTI Mobile (Capacitor 8)

Native Android/iOS shell that wraps the BLASTI Next.js web app (`apps/web`)
via [Capacitor 8](https://capacitorjs.com). All UI lives in the web app — this
package owns the native layer: plugins, permissions, icons, splash screen.

## Installed native plugins (16)

| Plugin | Purpose |
|---|---|
| `@capacitor/app` | Lifecycle, back button, `blasti://` deep links |
| `@capacitor/camera` | Take photos |
| `@capacitor/device` | Real device model / OS version |
| `@capacitor/filesystem` | Save + share downloaded files |
| `@capacitor/geolocation` | GPS (manifest has `ACCESS_FINE/COARSE_LOCATION`) |
| `@capacitor/haptics` | Vibration patterns |
| `@capacitor/local-notifications` | Turn alerts on a max-importance channel |
| `@capacitor/preferences` | Persistent native storage |
| `@capacitor/push-notifications` | FCM push (needs Firebase config, see below) |
| `@capacitor/share` | Native share sheet |
| `@capacitor/splash-screen` | Launch splash (BLASTI green) |
| `@capacitor/status-bar` | Status bar styling |
| `@capacitor-mlkit/barcode-scanning` | QR scanning (registered name `BarcodeScanner`) |
| `@capacitor-community/keep-awake` | Screen stays awake on agency dashboard (`window.__CAPACITOR_KEEP_AWAKE__`) |
| `@capgo/capacitor-native-biometric` | Fingerprint / Face ID (`NativeBiometric`) |
| `@capawesome/capacitor-badge` | App icon badge count (`Badge`) |

Sensors (accelerometer etc.) work out of the box via `DeviceMotionEvent`
— `@capacitor/motion` is a JS-only plugin on top of it.

## 🚀 Run the app in Android Studio (testing)

Prerequisites: **Android Studio** (Hedgehog or newer — its bundled JDK 21 works),
Android SDK 36, and either an emulator or a USB-connected device.

```bash
# from the repo root:

# 1. One-time: build the web export + sync it into the native project
bun run build:mobile

# 2. Open the project in Android Studio → press ▶ Run
bun run mobile:studio

# Or do build + sync + open in a single command:
bun run mobile:android

# Or run directly on a connected device/emulator without Android Studio UI:
bun run mobile:run
```

> Android Studio opens `apps/mobile/android`. The first Gradle sync downloads
> dependencies; then pick a device and press **Run**. `versionCode 2` /
> `versionName 1.0.0`.

### Live-reload development (no rebuild per change)

```bash
bun run dev            # starts api :3003 + web :3000
# in a second terminal, point the shell at your dev server (use your LAN IP):
cd apps/mobile
CAPACITOR_SERVER_URL=http://192.168.1.100:3000 bun run cap:sync:android
bun run studio
```

### After every web change (dev builds)

```bash
bun run build:mobile     # always re-sync — the native project embeds the web export
```

> `build:mobile` is a **DEV** build: discovery + manual server address stay
> available. See the production section below for the locked VPS APK.

## 🌍 Production (VPS) release APK — fixed server, no setup UI

The **release** build bakes ONE server address into the app and removes the
login screen's "Server connection" pill, manual-address dialog and Wi-Fi
scanning entirely — the app talks only to your VPS.

1. Edit **`apps/mobile/.env.production`**:

   ```env
   NEXT_PUBLIC_API_URL=http://68.183.137.227   # your VPS bare origin (no /api)
   NEXT_PUBLIC_SERVER_DISCOVERY=0              # lock: no manual input / no scan
   ```

2. Build + install — either of these (both read `.env.production`):

   ```bash
   cd apps/mobile && bun run build:android:release   # from the app folder
   bun run mobile:apk:release                        # from the repo root
   ```

Dev builds (`build:mobile`, `build:android`, `build:android:debug`,
`mobile:apk`) ignore `.env.production` and keep the discovery flow so the
phone can find the API running on your PC. To change the server later:
edit `.env.production` → rebuild → reinstall.

## 🔔 Enabling real FCM push

1. Create a Firebase project, add an **Android app** with package
   `com.blasti.mobile`, download `google-services.json` into
   `apps/mobile/android/app/` (the Gradle build picks it up automatically).
2. Generate a service-account private key (Firebase console → Project settings
   → Service accounts) and give it to the API either inline:
   `FIREBASE_SERVICE_ACCOUNT_JSON='{ ... }'` in `apps/api/.env`, or via
   `FIREBASE_SERVICE_ACCOUNT_PATH=/path/to/sa.json`.
3. The client registers automatically: on app boot the web layer requests
   notification permission, registers with FCM and POSTs the token to
   `POST /api/user/push-token` (auth cookie required).
4. The notification worker now tries **free FCM push before paid SMS** for
   every delayed turn alert.

Without Firebase config everything still works except remote push (local
notifications, WebSocket alerts and SMS fallback are unaffected).

## Alarm sound

`android/app/src/main/res/raw/blasti_alarm.wav` + `apps/web/public/blasti_alarm.wav`
are generated by `bun scripts/generate-alarm-wav.ts` (two-tone rising alert).
Regenerate if you want a different tone.

## iOS

`@capacitor/ios` is installed; run `bunx cap add ios` inside `apps/mobile` to
generate the Xcode project when you're ready (requires macOS + Xcode).
